# ADR-0001 follow-up — Local and distributed processing

**Accepted direction — Bacalhau for local and remote jobs.** Use WASI for portability and optional Docker for performance/native dependencies. Direct native jobs outside the runtime are excluded from the product. ADR-0001 concerns the runtime independently of the application stack and was **Accepted** on 2026-11-16; implementation alignment and operational readiness remain pending. Go + Wails is a separate decision in [ADR-0002](0002-adopt-go-wails-v3.md). The [technical trade-off case](0001-native-execution-tradeoff.md) explains the decision with graphs, raw artifacts and limitations; the comparison below records the alternatives considered.

| Option | Complexity and footprint | Latency and reproducibility | Strategic value |
| --- | --- | --- | --- |
| Bacalhau for all processing | A single scheduling authority and uniform job lifecycle. Every workstation runs and maintains a Bacalhau process, stages workers and handles job lifecycle. Distributed placement also needs topology, transport and evidence policy. | The same pinned WASI contract ran on Windows and Linux. The synthetic UFDR handler attempts took 1.61 and 1.90 s. Sequential WASI synthetic CPU cells added roughly 1.5–1.7 s outside worker compute. The measured arithmetic kernel was roughly 17 times slower inside WASI. | Consistent deployment contract from one workstation to multiple hosts. Pays distributed execution costs for work that never needs to leave the workstation. |
| Native Go locally, Bacalhau for authorized distributed execution | Lower default installation and idle footprint. Two execution adapters must report the same domain-level provenance. Bacalhau can remain the sole scheduler for distributed jobs. Local execution can be synchronous for the PoC. | The in-process Go route runs directly over the input buffer. Tested UFDR results were semantically identical across native and WASI runs. Pin and exercise both build outputs and preserve the per-attempt artifact identity. | Keeps a tested route to placement and future BYOC workloads. VIII retains a shared worker contract and owns the evidence policy in both modes. |
| Evaluate a different distributed orchestrator if the next gate fails | Adds adapter and lifecycle work. A custom scheduler would also inherit retry, cancellation, admission, resource management and support costs. | Unknown. A candidate would need to reproduce the exact worker, input identity and placement guarantees under an equivalent workload and resource budget. | Worth considering if Bacalhau cannot support cross-host authorization and recovery, or if a representative distributed workload cannot justify its measured cost. |

Select the first option for product jobs. The earlier native-first recommendation is superseded: lower measured local latency does not override the chosen common lifecycle and portable-worker goals. This accepts local orchestration overhead; lower total product cost remains unmeasured. Keep evidence identity, result identity and the authorization decision in VIII. Require explicit placement authorization before staging or submitting evidence, locally or remotely. Retain native execution only as a benchmark baseline, not a product fallback.

The [authorized execution and recovery experiment](../poc/authorized-execution-recovery.md) used isolated compute nodes on one physical workstation. The same staged synthetic UFDR workload produced identical hashes and source references across the native and WASI paths. Bacalhau's admission and scheduling selectors worked alongside VIII's separate evidence authorization. The application refused denied submissions before staging and retained the original bytes and attempt provenance independently of the scheduler.

An empty-report control produced a new execution on A after B died when both nodes were eligible. The evidence job was pinned to B. It remained Running for the 70-second Windows observation window and stopped after cancellation. In the Windows/Docker run, the pinned job failed 72.6 seconds after the kill. The orchestrator recorded a task timeout and found no suitable replacement node. There was no replacement execution in either case. VIII recovered the same job identity and its execution provenance after service reconstruction. A separately authorized manual retry completed on A in both runs.

The results demonstrate the shared job contract and some recovery behavior on one workstation. VIII still needs persistent attempt identity, recovery by job lookup, explicit cancellation and retry, and integrity checks for staged inputs and returned results. Permit scheduler failover only where every eligible node has been authorized for that evidence and the attempt model can preserve each execution. The current adapter rejects multiple executions. The staging and stdout return contract is sufficient for this synthetic experiment. Representative workloads require an authorized artifact return path before the operational cost can be assessed.

Use Bacalhau/WASI for the compatible Docker-free workstation workflow. Production-grade artifact transfer, a two-physical-host run, and operational cost for representative cross-host work remain acceptance gates. Installer, no-CLI first use and coordinated update gates remain open in [issue #9](https://github.com/vmenezesdev/viii-digital-evidence-workbench/issues/9). The merged PoC still defaults to native execution; implementation alignment is separate from this documentation revision.

The [executor comparison](../poc/executor-comparison.md) exercised both Bacalhau engines on one Linux compute node with identical synthetic work. Docker completed faster across the serial duration sweep. WASI paid module compilation on each job, while Docker paid for container startup and ran the native arithmetic kernel. Use WASI for compatible portable workers and Docker when performance or dependencies justify enabling it on a node. Each engine needs the same evidence identity, authorization and result provenance from VIII. Native code inside a Docker worker is within this direction; direct native desktop jobs are not.
